# Diablos Messenger Bot

بوت Node.js لمجموعات Messenger يستخدم `ws3-fca`. الأوامر موجودة في `cmd/`، ولا يقبل البوت الأوامر إلا من معرّف المطور المحدد.

## الإعداد

اضبط المتغيرات التالية في بيئة التشغيل:

- `FACEBOOK_DEVELOPER_ID` — معرّف حساب المطور الرقمي.
- `FACEBOOK_APPSTATE_JSON` — جلسة Facebook بصيغة مصفوفة JSON، تُحفظ كمتغير سري ولا تضاف إلى Git.

يمكن استخدام `appstate.json` محليًا بدل المتغير، لكن الملف مستثنى من Git؛ لا تنقله إلى استضافة أخرى ولا تضع محتواه في سجل الأوامر. إذا استُخدم `DIABLOS_DATA_DIR` تُحفظ إعدادات البادئات والمجموعات المعروفة ونسخ الحماية في هذا المجلد.

## التشغيل والاختبار

من جذر مساحة العمل:

```sh
pnpm start
pnpm --filter @workspace/scripts test
```

يشغّل زر التشغيل في Replit الأمر `cd Diablos-Facebook-Bot && pnpm start`. ومن جذر مجلد المشروع شغّل `pnpm start`. يبدأ الأمر مشغّلًا واحدًا، ويمنع قفل الجلسة تشغيل نسخة ثانية على الجهاز أو وحدة التخزين نفسها. يعيد المشغّل المحاولة تلقائيًا عند خروج عملية البوت، مع زيادة الفاصل بين المحاولات حتى دقيقة.

## Railway والاستضافات الأخرى

أنشئ خدمة عامل (Worker)، واجعل جذر المشروع مجلد `Diablos-Facebook-Bot`، وأوامر البناء والتشغيل:

```sh
pnpm install --frozen-lockfile
pnpm start
```

لا يحتاج البوت إلى منفذ ويب. أضف `FACEBOOK_DEVELOPER_ID` و`FACEBOOK_APPSTATE_JSON` إلى متغيرات البيئة السرية للخدمة. وللاحتفاظ بإعدادات البادئات ونسخ الحماية بعد إعادة النشر، اربط وحدة تخزين دائمة واضبط `DIABLOS_DATA_DIR` على مسار تركيبها، مثل `/data`.
يضبط `railway.json` نسخة تشغيل واحدة لتجنب فتح جلسة Facebook ثانية. ابدأ العامل من مجلد المشروع باستخدام `pnpm start`، ولا تشغّل أكثر من نسخة خدمة للبوت على وحدة التخزين نفسها.

## الأوامر

تبدأ الأوامر افتراضيًا بـ `!`، ويمكن تغيير البادئة لكل مجموعة:
ينفّذ البوت كل أمر بعد انتظار 5 ثوانٍ. في `!بيس` و`!devil` يحتوي رد البدء الأول على النص وتحته سطر الإيقاف؛ رسائل التكرار التالية تحتوي النص وحده. تعرض قائمة المساعدة أسماء الأوامر والاختصارات فقط بتنسيق افتراضي مع رموز تعبيرية.

- `!مساعدة`
- `!بادئة #` أو `!prefix #` — تغيير بادئة المجموعة.
- `!uptime` أو `!حالة` — حالة الاتصال والتكرار النشط.
- `!بيس` أو `!base` مع نص — تكرار بفاصل عشوائي من 15 أو 19 أو 29 أو 34 ثانية. الإيقاف أو الحالة: `!بيس إيقاف` أو `!بيس حالة`.
- `!devil` أو `!شيطان` مع نص — تكرار بفاصل ثابت قدره 60 ثانية. الإيقاف أو الحالة: `!devil إيقاف` أو `!devil حالة`.
- `!اسم` أو `!name` مع الاسم الجديد، أو `!اسم عرض` للاطلاع على الاسم الحالي.
- `!كنيات` أو `!nicknames` مع الكنية — تطبيق الكنية على الأعضاء؛ `إيقاف` يلغي التحديث الجاري.
- `!إزالة_الكنيات` أو `!clear-nicknames` — إزالة كنيات الأعضاء مع متابعة بقية الأعضاء إذا تعذر تحديث أحدهم.
- `!حماية` أو `!protect تشغيل` — حفظ اسم المجموعة وكنياتها وبدء الاستعادة فورًا بعد التغيير. الحالة: `!protect status`، والإيقاف: `!حماية إيقاف`.
- `!إعادة` أو `!reset` — حذف كل ملفات نسخ الحماية من مجلد `Nike` لكل المجموعات؛ للمطوّر الأساسي فقط. تُلغى الاستعادات المعلّقة، ولا يمكن استعادة البيانات المحذوفة إلا بإنشاء نسخ جديدة.
- `!خروج` أو `!leave` — إرسال طلب لمغادرة البوت للمجموعة الحالية؛ للمطوّر الأساسي فقط. استخدمه من داخل المجموعة المقصودة.

تعرض `!مساعدة` و`!help` قائمة بسيطة بأسماء الأوامر بالعربية والإنجليزية، دون شروحات.

للبوت كنية ثابتة هي `D̲i̲a̲b̲l̲o̲s̲꙰ │ ➯〘🇷🇺〙`. عند انضمامه إلى مجموعة أو تلقي حدث تغيير كنية، يفحص البوت عضويته والكنية بعد 5 ثوانٍ، ولا يرسل التغيير إذا كانت الكنية صحيحة. يعتمد نجاح تغيير الاسم أو الكنيات على ما تسمح به واجهة Messenger لحساب البوت؛ إزالة شرط المشرف من الكود لا تتجاوز رفض المنصة.

## ملاحظة

`ws3-fca` مكتبة غير رسمية تعتمد على جلسة حساب Facebook؛ قد تتغير طريقة عملها أو تفرض المنصة قيودًا على الجلسة أو الحساب. استخدم حسابًا تملكه ومجموعات تديرها.
